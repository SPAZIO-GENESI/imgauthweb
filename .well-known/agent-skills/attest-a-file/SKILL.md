# Attest a file with Spazio Genesi

This skill produces a **proof of existence** for any file: a server-timestamped,
HMAC-signed attestation, a signed PDF certificate, and a permanent public
verification page. It proves that *this exact content* existed at *that moment*.
It does **not** prove authorship — see "What this does not prove" below.

Service operated by Spazio Genesi ETS, a non-profit in Italy. Free, no account
required.

## The one thing that matters

**The file never leaves the machine.** You compute its SHA-256 fingerprint
locally and send only those 64 hexadecimal characters. The API has no endpoint
that receives file content in the recommended path. Never read a whole file into
a tool argument — stream it through a hash function instead.

```bash
sha256sum myfile.pdf        # Linux
shasum -a 256 myfile.pdf    # macOS
certutil -hashfile myfile.pdf SHA256   # Windows
```

## Fastest path: use the existing clients

Before writing HTTP calls, prefer the maintained clients — they already do the
local streaming hash, the authorization dance and the error handling:

- **Command line / CI:** `npx -y @spazio-genesi/attest-mcp sg-attest attest myfile.pdf --pdf`
  (standalone binaries for Linux/macOS/Windows are published on GitHub Releases,
  no Node.js needed)
- **GitHub Actions:** `SPAZIO-GENESI/attest-action@v1`
- **MCP, local (can read files):** `npx -y @spazio-genesi/attest-mcp`
- **MCP, remote (zero install):** `https://attest-mcp-remote.it-e3f.workers.dev/mcp`

Use the raw HTTP flow below only when none of those fit.

## Step 1 — get a credential

Attesting requires a credential; verifying never does. Two options, described in
full at <https://attestazione.spaziogenesi.org/auth.md>:

**A. Device flow — no identity, no email, ~1 minute.** Best for agents.

```http
POST https://imgauth.spaziogenesi.org/api/agent/authorize
```

Returns `{ "code": "...", "verification_url": "...", "expires_in": 600, "interval": 3 }`.

Show `verification_url` to the human. They open it and clear an anti-bot
challenge — **this step is deliberately not automatable**: an attestation that no
human ever asked for would not prove the same thing. Then poll:

```http
GET https://imgauth.spaziogenesi.org/api/agent/token?code=<code>
```

- `{"status":"pending"}` → wait `interval` seconds and retry
- `{"status":"approved","token":"sg_s_..."}` → **returned exactly once**, store it
- `{"status":"claimed"}` → someone already collected it; you missed it
- `410 {"status":"expired"}` → start over

The session token is valid **24 hours / 20 attestations**.

**B. API key** `sg_k_…` — obtained once at
<https://attestazione.spaziogenesi.org/developer/keys/> by verifying an email
address (Google, Microsoft or LinkedIn, one-shot: no session is created and the
provider token is discarded). Does not expire, 50 attestations/month.

Send either as `Authorization: Bearer <token>`. **Never place a credential in a
command-line argument or a tool parameter** — it would end up in shell history,
process lists and model context. Use an environment variable.

## Step 2 — create the attestation

```http
POST https://imgauth.spaziogenesi.org/api/hash
Authorization: Bearer sg_s_...
Content-Type: application/json

{
  "sha256": "<64 hex chars, computed locally>",
  "name": "myfile.pdf",
  "type": "application/pdf",
  "size": 182344,
  "titolo": "optional declared title",
  "autore": "optional declared author",
  "anno": "optional declared year",
  "note": "optional declared notes"
}
```

The response contains the **timestamp generated by the server** (never by you —
that is what makes back-dating impossible), the attestation string
`SHA-256:<hash>@<timestamp_iso>` and its HMAC signature:

```json
{
  "sha256": "...", "timestamp_iso": "...", "timestamp_leggibile": "...",
  "attestazione": "SHA-256:...@...", "hmac": "...", "emesso_da": "..."
}
```

⚠️ **Keep the whole response.** The four optional declared fields are bound into
the signature: to verify later you must supply them **byte-identical**. The
server normalises them (whitespace collapsed, length capped, non-WinAnsi
characters dropped), so trust the values it returns, not the ones you sent.

Add `"lang": "en"` for English error messages and an English certificate. The
language never enters the signature: a certificate in English and one in Italian
verify identically.

## Step 3 — get the certificate, or nothing is archived

⚠️⚠️ **This step is not optional if you want the file to be verifiable later.**
`/api/hash` alone signs an attestation but **archives nothing**: the permanent
page `/c/<hash>` will return 404 and the public badge will stay grey. Only
`/api/cert-pdf` archives.

```http
POST https://imgauth.spaziogenesi.org/api/cert-pdf
Content-Type: application/json

<the entire JSON object returned by /api/hash, including attestazione and hmac>
```

Returns the PDF bytes, cryptographically signed (PAdES with an RFC 3161
timestamp) and archived. As a side effect the fingerprint is anchored to Bitcoin
via OpenTimestamps, and this becomes live:

```
https://attestazione.spaziogenesi.org/c/<sha256>
```

Report that URL to the user — but only after `/api/cert-pdf` has succeeded.
Announcing it earlier hands them a 404 dressed up as success.

## Errors worth handling

| Status | Meaning | What to do |
|---|---|---|
| 400 | malformed fingerprint, or missing anti-bot token without a credential | check the hash is 64 hex chars |
| 403 | credential invalid, revoked or expired | get a new one (step 1) |
| 429 | rate limit (60/min on hash, 10/min on certificates) or quota exhausted | back off; check remaining quota |
| 503 | signing not configured | transient service problem, retry later |

The response of `/api/hash` may also report a lower tier (`fascia`) with a reason
(`fascia_motivo`) when a shared quota is spent. That is a **degradation, never a
block**: the attestation is still issued and still valid.

## What this does not prove

Be honest with the user about this — the service is:

- **Not proof of authorship.** It proves the content existed at that time.
  Declared title/author/year are self-declarations, labelled as such on the
  certificate.
- **Not a qualified eIDAS trust service.** The timestamp comes from an
  AATL-trusted authority and the fingerprint is anchored to Bitcoin, but the
  signer identity is self-certified. See the whitepaper:
  <https://attestazione.trust.spaziogenesi.org/whitepaper-v1.0.pdf>
- **Not a backup.** Only the certificate is archived, never the work itself.
